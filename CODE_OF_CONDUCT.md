# Code of conduct

## The short version

Be decent. Disagree about code, not about people. Assume the person you are
replying to is acting in good faith until they show you otherwise.

## Expected

- Critique the change, not the contributor.
- If you are wrong, say so plainly and move on. That is faster than defending a
  mistake.
- Respect that this project has stated limits. "It would be more useful if it
  tracked people" is a proposal to build something else.

## Not acceptable

- Harassment, personal attacks, or sustained disruption
- Publishing someone's private information, even in a bug report. Redact logs,
  hashes, addresses and message identifiers before posting.
- Pressuring maintainers to add capabilities that `docs/ethics.md` rules out
- Using the issue tracker to request help analysing a specific person

That last one is not about manners. PHANTOM's whole architecture exists so that it
cannot become a tool for that, and requests to bend it are declined.

## Scope

This applies to issues, pull requests, discussions, and any space where you are
representing the project.

## Enforcement

Maintainers may edit or remove contributions that break these rules, and may block
repeat offenders. If something happens that you would rather not raise in public,
contact the maintainer privately.
